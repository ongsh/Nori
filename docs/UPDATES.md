# 网页检查与更新（Linux / WSL2）

当前版本支持受管启动器下的网页切换与重启。首次从旧版迁移的边界见下文。

1. 点击网页右上角“检查更新”，核对目标版本和固定提交。检查不会下载或安装。
2. 确认更新与重启后，程序下载并校验固定版本。在受管启动器下，空闲检查通过才切换版本、重启本地服务，并在原网页等待重新连接。无需复制安装命令。
3. 存在活动或无法确认已停止的任务、其他 Nori 进程、损坏/无法核对的项目状态时，不强制终止它们，也不宣布更新完成。先处理提示中的阻碍，再明确尝试重启。下载成功不等于已切换。
4. 新版启动与健康检查失败时，只有确认候选进程退出后才恢复上一版。无法确认退出就保守阻塞，不启动竞争服务；页面会给出失败或超时提示。项目数据不随程序版本回滚。
5. 回退也需明确确认。待更新尚未生效时可取消；需要恢复上一版时使用回退入口。若网页无法打开，可关闭其他 Nori 进程后运行 `~/.local/bin/nori --rollback`。跨版本数据格式不保证可逆，遇到格式不兼容应保留数据并停止操作。

## 从旧启动器迁移

1.0.6-preview 及更早版本的启动器没有驻留的进程管理能力，不能从旧网页凭空接管并自动重启。先用旧网页下载此版本，然后最后一次关闭旧服务并运行 `~/.local/bin/nori`。新版会升级已识别的受管启动器并启用重启管理，不需要重新下载或克隆仓库。此后更新可在网页完成。

回退到尚不支持受管重启的旧版本时，网页会在停止当前服务之前拒绝自动切换；仍需手动重启。若端口被其他程序占用，Nori 不会强杀占用者或强行清理端口。

终端仍是 Nori 的启动入口，应保持打开；本功能不是系统后台服务或开机启动。源码运行不支持程序自更新。
服务仍只监听本机；不需要 sudo，不自动提权，不公开端口。源码运行不等同于已安装程序，不能从网页替换源码目录。原生 Windows 不支持，Windows 请在 WSL2 内运行。

## 更新来源与完整性

更新来源固定为 `ongsh/Nori` 的 `codex/nori-p1-rebuild-20261107` 分支下的 `distribution/update.json`。它是由维护者在载荷提交通过 CI 后推进的稳定指针，包含版本、不可变提交、SHA-256 和大小。客户端只从对应固定提交读取分发包，不从用户输入的 URL 下载，也不下载执行在线安装脚本。

校验用于确认下载字节与指定发布内容一致，并非独立签名。维护者账户、仓库或其发布流程被攻破时，同源校验值也可能被修改。HTTPS、固定来源与 SHA-256 不能保证代码本身没有漏洞。当前不宣称具备签名更新或同账户攻击隔离。

更新需要显式确认；不会定时静默安装。下载、暂存和启动切换分别受锁保护。旧程序文件保留以支持回滚；用户数据始终与安装目录分离。

## 发布顺序

维护者先构建可重复 zipapp，提交代码、分发包及安装脚本中的校验值；等待该提交全部 CI（含浏览器测试）通过。之后单独提交 `distribution/update.json`，指向已通过的载荷提交。不要在载荷测试完成前将开发分支 HEAD 直接视为稳定版本。

公共缓存可能短暂返回较早的发布清单。更新入口不会因此安装较低版本；无法比较的版本也会保守拒绝。回退必须走单独的显式回滚入口。
