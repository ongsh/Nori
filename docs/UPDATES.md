# 网页检查与更新（Linux / WSL2）

首次需要安装带更新功能的版本。升级旧版前先关闭旧 Nori 服务；旧版启动器尚没有运行锁，不能由新版本替它证明已经退出。之后打开网页右上角的“版本与更新”：

1. 查看当前运行版本，点击“检查更新”。这一步只读取版本信息，不下载或安装程序。
2. 确认显示的目标版本和固定提交，再点击下载更新。失败不会切换当前程序，项目与脑图数据不变。
3. 下载并校验成功后，先保存编辑，暂停正在执行的项目并确认执行器已退出。关闭当前服务，再运行 `~/.local/bin/nori`。更新在下一次启动生效，不会替换正在使用的程序文件。
4. 如果需要返回上一版，在同一面板明确选择回滚，再关闭并重新启动。待更新尚未生效时，按钮会改为“取消待生效更新”。如果新版网页无法启动，关闭其他 Nori 进程后运行 `~/.local/bin/nori --rollback`，可由独立启动器回退，不依赖新版应用成功导入。回滚程序不回滚或删除项目数据；跨版本数据格式不保证可逆，遇到格式不兼容应保留数据并停止操作。

服务仍只监听本机；不需要 sudo，不自动提权，不公开端口。源码运行不等同于已安装程序，不能从网页替换源码目录。原生 Windows 不支持，Windows 请在 WSL2 内运行。

## 更新来源与完整性

更新来源固定为 `ongsh/Nori` 的 `codex/nori-p1-rebuild-20261107` 分支下的 `distribution/update.json`。它是由维护者在载荷提交通过 CI 后推进的稳定指针，包含版本、不可变提交、SHA-256 和大小。客户端只从对应固定提交读取分发包，不从用户输入的 URL 下载，也不下载执行在线安装脚本。

校验用于确认下载字节与指定发布内容一致，并非独立签名。维护者账户、仓库或其发布流程被攻破时，同源校验值也可能被修改。HTTPS、固定来源与 SHA-256 不能保证代码本身没有漏洞。当前不宣称具备签名更新或同账户攻击隔离。

更新需要显式确认；不会定时静默安装。下载、暂存和启动切换分别受锁保护。旧程序文件保留以支持回滚；用户数据始终与安装目录分离。

## 发布顺序

维护者先构建可重复 zipapp，提交代码、分发包及安装脚本中的校验值；等待该提交全部 CI（含浏览器测试）通过。之后单独提交 `distribution/update.json`，指向已通过的载荷提交。不要在载荷测试完成前将开发分支 HEAD 直接视为稳定版本。

公共缓存可能短暂返回较早的发布清单。更新入口不会因此安装较低版本；无法比较的版本也会保守拒绝。回退必须走单独的显式回滚入口。
